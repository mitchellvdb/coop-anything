DDCoop test74 - normal session / weekly activity regression
Use the same test74 kit on every PC. Solo multi-window testing uses duo57.

1. Close all games before installing. Install with the usual DDCoop installer.
2. Host or join a campaign. Each player may prepare the party, provision and embark.
3. In the Tavern or Abbey, drag a hero into an available activity slot without
   pressing Accept. Everyone should see the same reserved hero. Another player
   should not be able to replace that draft with a different hero.
4. Accept or cancel from another player. Confirm one shared payment/assignment.
5. Play and finish a normal mission, return to the Hamlet and continue playing.
   Automatic weekly activity processing should not display the old reserved-slot
   warning. A party wipe is not required for this check.
6. Check party, money and active Tavern/Abbey occupants on every copy. Try another
   reservation after the return. If a warning or desync occurs, stop and Copy logs.
7. When convenient, retain the test73 interaction checks: obstacle hand/tool,
   curio item/X and normal food. These are not all confirmed by the last live log.

Guests always run -nosave. Host saving follows its checkbox. Backups/restore use
selected slots1..9; profile_9 is never a co-op slot. The host game and launcher
must stay running, but guests do not require a manual host click for shared actions.
Resync uses the host checkpoint and may lose unsaved progress. Solo batch guests
still restart manually. Do not mix runtime versions.
